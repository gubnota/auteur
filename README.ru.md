Новые задания используют сохранённые поля; выбирайте материалы из галереи или перетаскивайте файлы. Соответствие облачному workflow подтверждено пользователем; платный запуск не проверялся.

**0.1.9** исправляет проверку оборудования до загрузки: она ошибочно отклоняла CUDA-workflow на RunningHub. В **Jobs** используйте **Reuse** для неудачной попытки, проверьте сохранённые изображения и аккаунт, затем запустите новый черновик. Старая квитанция об ошибке остаётся в истории.

**0.1.11** использует документированный API загрузки ресурсов для workflow RunningHub и сохраняет безопасные текстовые причины отказа. Код **605** не документирован; несоответствие API загрузки исправлено, но успешный реальный запуск ещё не подтверждён. Старые квитанции неизменны. Создайте новый проверяемый черновик через Reuse as draft для исправленного адаптера.

В **Workflows → Reusable inputs** один раз настройте точные поля: подписи, роли изображений/видео/аудио, текст, числа, boolean, JSON, Advanced и Hidden. Уже назначенные поля помечены; повторные привязки блокируются. Повторный импорт сохраняет ID и внешнюю ссылку до явного Collect. Постеры видео, сокращение имён, Welcome и очистка недавних фильмов доступны. См. [настройку](docs/WORKFLOW_SETUP.md) и [проверки](docs/GENERATION_ACCEPTANCE.md).

## Текущая main: Generate и переносимая настройка

**Generate** использует одну рабочую область Custom для изображений, видео и аудио, самостоятельных заданий и кадров раскадровки. Выберите сохранённые workflow и узел, назначьте материалы и значения, проверьте пакет. **Add to queue** сохраняет его без запуска; **Jobs → Run queued batch / Run all queued** запускает. Одна инстанция ComfyUI обрабатывает очередь, разные работают параллельно.

В **Workflows → Compatibility & initialization** доступны флаги Unspecified, Universal, Apple Silicon, CUDA, ROCm и CPU, а также источники моделей, плагинов и Python wheels, хеши, лицензии и папки назначения. [Команды настройки](docs/WORKFLOW_SETUP.md) описывают Python инстанции, реальные папки моделей, установку плагинов, приватное хранилище, перезапуск и тест новой сессии. [Подключение RunPod/Colab](deploy/runpod/README.md) объясняет получение HTTPS-адреса relay.

Версия **0.1.6** использует схему **v4**: обновление v1/v2/v3 требует подтверждения и резервной копии. Нативная сборка и безопасные локальные GPU-тесты прошли; [результаты проверки](docs/GENERATION_ACCEPTANCE.md) отдельно описывают реальные запуски, проверки интерфейса и ожидающий проверки облачный узел.

Приложение macOS версии 0.1.6 ранее выполнило Generate → Jobs → Renders с сохранённым editor workflow и локальным узлом: получен PNG 64 × 114 в формате 9:16. Формат сохранился после повторного открытия фильма.

## Работа с фильмом

Создайте фильм и выберите папку либо откройте существующий `.mymovie`. Редактируйте названия фильма и эпизодов, добавляйте сцены и планы, упорядочивайте ключевые кадры. Для кадров доступны промпты, комментарии, формат изображения и персонажи. Персонажи сцены наследуются её кадрами.

Референсы персонажей можно импортировать в редакторе персонажа. Обработка перетаскивания файлов реализована для персонажей, библиотеки, кадров, планов и новых сцен. Проверка настоящего перетаскивания из Finder пока не завершена; если файл не принимается, используйте кнопку импорта.

## Копирование или ссылки на материалы

В **Media imports** доступны два режима:

- **Copy into movie** — по умолчанию: оригиналы копируются в пакет, одинаковые файлы определяются по содержимому.
- **Keep original location** — сохраняется ссылка без копирования. Исходный файл должен оставаться доступным.

Режим применяется к изображениям, видео, аудио и поддерживаемым файлам LoRA, включая референсы персонажей. Определения рабочих процессов импортируются отдельно внутрь фильма.

Библиотека показывает исходные пути. **Check files** проверяет отсутствие и изменение оригиналов. **Relink** позволяет указать тот же файл в новом месте; содержимое должно точно совпадать. Связи с кадрами и персонажами сохраняются.

Перед переносом нажмите **Collect for export**: приложение проверит и скопирует все внешние материалы в текущий `.mymovie`, сохранив назначения. Недоступные или изменённые оригиналы останавливают сбор. Закройте фильм и скопируйте весь пакет через Finder. Отдельный мастер создания архива или экспортной копии пока не реализован.

Импорт через системный диалог и сбор внешнего референса персонажа проверены в приложении macOS.

## Рабочие процессы и подключения

Импортируйте editor или API workflow один раз через **Browse workflow catalogue**. Подготовьте editor workflow на выбранном ComfyUI с [зависимостями компилятора](docs/WORKFLOW_SETUP.md). В **Workflows → Reusable inputs** один раз сохраните точные поля, подписи, роли и видимость. Поля API без реестра помечены как непроверенные. Старые или изменившиеся профили ComfyUI обновляются перед новой проверкой/фиксацией; ошибка сохраняет черновик. Неподдерживаемые сериализаторы и смена динамических ветвей требуют исправления/экспорта. Исходные графы и старые попытки неизменны.

**Customize input form** сохраняет названия, группы, порядок и выбранные результаты. Соотношение сторон меняет только привязанные width/height; выберите нужную пару, если их несколько. Раскрытие другой динамической ветки требует повторной подготовки. **Export API** использует подготовленный профиль выбранного узла. Настройка Python, Playwright и Chromium: [WORKFLOW_SETUP](docs/WORKFLOW_SETUP.md). Для RunningHub повторно используется сохранённый авторизованный deployment; произвольные графы автоматически там не публикуются.

Для API workflow задайте точные поля в **Workflows → Reusable inputs**, затем используйте сохранённую форму для новых заданий. Слоты `characterReference1`–`characterReference4` используют референсы назначенных персонажей; приложение не угадывает номера узлов.

Можно добавить несколько подключений ComfyUI, RunningHub и приватного relay. Помощь с промптами через Google, DeepSeek и OpenRouter опциональна. Вводите секреты через защищённые элементы приложения: они хранятся в Связке ключей macOS. Для fal и произвольных API пока доступна только настройка подключения.

Квитанции заданий и результаты сохраняются. Неоднозначная отправка получает статус unknown без слепого повторного запуска. Relay поддерживает SSE с повторным чтением событий; приложение пока использует опрос. Доступны прогресс в Dock, системные уведомления и отдельные журналы уведомлений/логов.

## Jobs: точные входы и пакеты заданий

Создайте или откройте пакет в **Generate**; команды workflow/кадра открывают тот же редактор. Добавляйте, удаляйте, дублируйте и упорядочивайте независимые элементы. Каждый использует сохранённый узел и форму workflow. Точные значения сохраняют пустую строку, ноль, false и JSON. Галерея показывает плитки, поиск и занятые изображения, назначает существующие ID без копирования. **Jobs** содержит очередь/историю и открывает Edit/Reuse в Generate.

**Review exact inputs** проверяет весь пакет до загрузок. Предпросмотр показывает хеши материалов; итоговые граф и payload сохраняются в квитанции. **Add to queue** фиксирует пакет без запуска; **Run now** запускает. Save queue changes атомарно заменяет только незапущенные попытки, сохраняя отменённые оригиналы. Передача результата между workflow пока не реализована.

Один нормализованный адрес ComfyUI получает задания по FIFO, даже при нескольких записях соединения. Разные адреса запускаются параллельно. Для relay очередь определяется адресом relay и node ID: создайте отдельное соединение для каждого RunPod GPU worker. RunningHub учитывает лимит параллельности аккаунта. Разные URL-алиасы одного сервера автоматически не распознаются.

Pause останавливает ожидающие элементы; Cancel также отправляет запрос отмены активных. После повторного открытия неотправленные элементы приостановлены до **Resume waiting**. Неопределённая отправка блокирует свою очередь до сверки истории; другие узлы продолжают работу. История Runs и происхождение Renders сохраняют run/item ID и точные снимки входов.

Обновление схемы сохраняет копии SQLite и manifest в `backups/` внутри пакета. Для работы старой версией сохраните полную копию исходного проекта.

## Приватный ComfyUI на RunPod

[Инструкция агента RunPod](deploy/runpod/README.md) описывает установку готового Linux x86_64/ARM64 артефакта CI рядом с приватным ComfyUI. Агент подключается исходящим HTTPS к аутентифицированному relay; публичный порт ComfyUI не нужен. CI включает ELF-бинарник, инструкцию, метаданные и SHA-256. Веса и custom nodes должны быть установлены заранее. Автоматическая синхронизация LoRA/runtime через S3 и живой полный тест RunPod/GPU остаются незавершёнными.

## RunningHub: создание задания

1. Добавьте аккаунт RunningHub в **Connections** и сохраните ключ через защищённый элемент для учётных данных.
2. Импортируйте API-workflow в **Workflows**. В **RunningHub deployments** выберите аккаунт, семейство API (**Workflow** или **AI App**) и ID именно этой опубликованной версии. JSON графа не подтверждает наличие deployment на сервере; нельзя подставлять ID другого AI App. Общий ID аккаунта необязателен.
3. Настройте **Reusable inputs**: номера узлов, имена полей и типы значений должны совпадать со схемой API deployment. Слоты референсов используют персонажей сцены/кадра.
4. Выберите **Target keyframe**, нажмите **Create generation job**, затем выберите аккаунт, проверьте значения и нажмите **Review exact inputs** → **Add to queue / Run now**. Диалог объясняет, каких настроек не хватает.

Отказ провайдера переводит задание в failed. При неопределённом результате отправки проверьте историю RunningHub и через **Resolve submission** привяжите существующий task ID либо подтвердите, что задание не создано, прежде чем повторять. Аккаунт и deployment фиксируются в квитанции задания.

Интерфейс и протокол проверены на тестовых данных; платная генерация RunningHub не проверена. Предоставленная [страница Workflow](https://www.runninghub.ai/workflow/2110044532631932930) задаёт семейство **Workflow** и ID `2110044532631932930`. Пользователь подтвердил соответствие этого ID предоставленному LTX API JSON; публичные детали графа независимо не проверены. Строковые привязки: `positivePrompt → 121.text`, `negativePrompt → 110.text`, `image → 167.image`. Перед отправкой назначьте изображение целевому кадру; нативная команда отклоняет задание без изображения.

## Артефакты CI и ноутбуки

[Руководство по сборкам и релизам](docs/CI_RELEASES.md) описывает `.gitlab-ci.yml`, GitHub Actions, DMG для macOS ARM/Intel, установщики Windows x64 MSI/EXE, пакеты Linux и клиент ComfyUI для Linux x86_64/ARM64. Версия тега должна совпадать с приложением; релизы содержат контрольные суммы. Успешные теги публикуют полный предварительный релиз GitHub после проверки всех сборок. Текущий remote — GitHub; для GitLab нужны проект и подходящий macOS runner.

Ноутбуки [Colab](deploy/colab) и [Kaggle](deploy/kaggle) разворачивают проверенный артефакт клиента рядом с установленным ComfyUI. Kaggle поддерживает два независимых GPU-процесса с отдельными портами и node ID. Живое развёртывание требует защищённого relay и активной среды, разрешающей такую работу.

## Разработка

Требуются Apple Silicon, macOS 13+, Xcode Command Line Tools, Rust и Node.js/npm.

```sh
npm ci
npm run tauri:dev
npm run tauri:build -- --debug --bundles app
```

Неподписанная сборка: `target/debug/bundle/macos/MyMovie Studio.app`. Браузерный просмотр (`npm run dev`) хранит временные данные в памяти; проверяйте файлы и пакеты в нативном приложении.

```sh
npm run typecheck
npm test -- --maxWorkers=1
cargo test --workspace
```

## Проверка на CPU

```sh
docker compose -f deploy/cpu/compose.yaml up -d --build
python3 scripts/cpu-smoke.py
```

Движок OrbStack/Docker должен работать; окно OrbStack можно закрыть. Лёгкая проверка без весов моделей подтвердила доступность ComfyUI, отправку, историю и загрузку результата. Это не проверка GPU-процессов генерации видео.

## Текущие ограничения

Реальная генерация RunningHub, удалённый relay/S3/RunPod, notebooks в облаке, нотарификация и жесты Finder ещё требуют проверки. Локальные экспорт editor→API и FaceSwap с весами проверены; результаты собраны с хешами и происхождением задания. Произвольные custom plugins требуют совместимого frontend и проверки зависимостей. Профили браузера, обучение LoRA и полный FFmpeg pipeline остаются будущими этапами.
